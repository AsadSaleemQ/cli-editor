### Low

**L-1 — A native CLI removed after installation surfaces as a raw I/O error with the wrong exit class instead of the actionable target-missing error.**
`src/dispatcher.rs:357-360` (`validate_native_metadata`) and `src/discovery.rs:131-134` (`resolve_recorded_target`).

Both map any `canonicalize` failure through `CliEditorError::io`, which `src/error.rs:122` classifies as exit 125. Failure scenario: a user runs `npm uninstall -g @anthropic-ai/claude-code`; `claude` still resolves to the CLI Editor shim, and `run_managed` prints `cli-editor: I/O error at <...>\claude.exe: The system cannot find the file specified.` and exits 125. The user gets neither the shell's "not recognized" nor the guidance that already exists in `TargetNotFound` ("after installing it, run `cli-editor repair --adopt-native <codex|claude>`", `src/error.rs:13-16`, exit 126). `cli-editor doctor` reports the same raw string as its detail (`src/doctor.rs:118`). Recommended correction: in `validate_native_metadata` and `resolve_recorded_target`, special-case `std::io::ErrorKind::NotFound` on the recorded path to a named condition — either thread `kind` through and return `TargetNotFound(kind)`, or add a `NativeTargetMissing(PathBuf)` variant in the 126 class whose message names both `repair --adopt-native` and `uninstall`.

**L-2 — `cli-editor install` run from the documented post-install terminal fails with a bare I/O error, so the idempotent "already installed" path is unreachable.**
`src/installer.rs:48-66` and `:195-197`.

`install` derives the bundle from `current_exe()`'s parent. `README.md:9-15` tells the user to install, then open a new terminal — in which `cli-editor` resolves to `%LOCALAPPDATA%\CLIEditor\shims\cli-editor.exe`. Failure scenario: the user re-runs `cli-editor install` (to re-check, or after a doctor warning); `source_directory` is the shims directory, which by design contains no bundle, so `verify_release_bundle` fails at `:818-819` with `I/O error at <...>\shims\compatibility-manifest.json`. The message at `:195-197` ("already installed; existing state was revalidated and republished") — added for round-5 L-2 — can only be reached by re-running the extracted bundle copy. Recommended correction: at the top of `install`, detect that `current_exe()` is inside the owned root (the check already exists at `:279-285` for `update`) and either short-circuit to the already-installed message when state loads, or return a specific error naming the extracted release directory.
